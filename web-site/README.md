# NoteFusion public web

The marketing site, public policies and account self-service pages. No build step,
no framework — plain HTML, responsive CSS, and small scripts. Open `index.html` in a
browser and you are looking at production.

The legacy device screenshots, social share card and icons are derived from
`mobile/assets/` and should be rebuilt, not hand-edited. The script lives at the
repo root, outside the deploy root, so it is never served over the network:

```bash

```

It still resizes the original app screens and draws social/share imagery.

## Design rules

One set of rules for the public site, the generated blog and hymn pages and the web app:

- **Type**: Geist for the interface and reading text, Source Serif 4 for headlines, JetBrains Mono for
  solfa; one scale (48 / 36 / 28 / 20 / 16 / 14); tabular numerals for prices and figures.
- **Shape and space**: 8px controls, 12px panels, 1px hairlines, multiples of 8 for spacing; one quiet
  shadow for things that float. No gradients, glows, frosted glass or hover-lift.
- **Colour**: neutrals carry the page; brand blue (#2563EB day, #2F7BFF night, with #1B5FE0 under white
  text) for primary actions, links and focus; amber only for Pro. Text is 4.5:1 or better in both themes.
- **Layout**: sections are left-aligned under a plain heading and divided by hairlines; no eyebrow labels
  above headings, no numbered step cards, no icon tiles or pill badges on features.
- **Icons**: Lucide only, from `assets/icons.svg` (`<svg class="ic" aria-hidden="true"><use
  href="/assets/icons.svg#i-mic"/></svg>`), stroke 1.75, 16 / 20 / 24 px, `currentColor`, and only where they
  help scanning. To add one, list it in `tools/blog/icons.mjs` and run the build. Brand marks (the
  NoteFusion mark, Google, Google Play, the link providers, Product Hunt) stay as they are.
- **Phones first**: base styles are a phone's (360–414 px), `min-width` queries go upward; a control is at least
  44 x 44 px (an inline link grows its hit area with padding its negative margin gives back), a field's text 16 px;
  compact desktop sizes come back only under `(min-width: …) and (hover: hover) and (pointer: fine)`.
- **Show the product**: the home page shows real output (the engine's solfa and the OSMD staff for a hymn
  from the hymnal, written into `index.html` by the build) and real screenshots of the web app, never a
  drawing of an interface. To retake the screenshots, open a hymn in `/app` against a mocked API at
  1200x800, 2x, day and night, then run `python tools/build-assets.py` for the phone-sized variants.

Kept in `web-site/` rather than `docs/` deliberately: GitHub Pages' zero-config
option serves `docs/` wholesale, and that folder holds `NoteFusion_PRD.docx` and
`NoteFusion_TRD.docx` — publishing it would put the product requirements on the
open internet.

The admin dashboard is a separate application (`web-admin/`) with its own deploy.
This directory is public. The one signed-in page is `app/`, which talks to the API from
the browser with the same bearer-token flow as the admin dashboard; the API's CORS list
must carry the site's origin (`Cors__AllowedOrigins__1` in `docker-compose.prod.yml`).

## Design tokens

`assets/site-pages.css` carries the public site's palette for both themes (`--page-*`, plus the
`--color-*` names the shared recorder and range picker read). The web app's palette is `theme.css` +
`night.css`. Values stay local to the website, so product/mobile theme changes do not silently recolour it.

The brand mark ships as a white silhouette with alpha. The app recolours it per
surface with React Native's `tintColor`; the web equivalent is `mask` +
`background-color`, which is what `.mark` does.

## Deploying

**Vercel** — point a project at this directory.

```bash
npx vercel deploy web-site --prod
```

`vercel.json` turns on clean URLs (so `/privacy` serves `privacy/index.html`),
sets `nosniff`, `DENY` framing, and a strict referrer policy, and caches
`/assets/*` for a week: fonts for a year (their names carry the upstream version), CSS and JS
for a day when requested with `?v=` (so **a changed CSS or JS file must get a new `?v=`** in every
page that loads it, and in `tools/blog/lib/site.mjs` for generated pages), and an unversioned CSS/JS/SVG
request is revalidated every time. There is no `/` redirect any more — the root is the
landing page.

Everything in this directory is served publicly. Nothing that is not meant to be
downloaded by a stranger belongs here; that is why the asset build script sits in
`../tools/` instead.

## Performance budget

Most visitors are on a mid-range Android phone on Nigerian 3G/4G, so every public page is held to this on
Lighthouse's mobile profile (simulated slow 4G, 4x CPU slowdown), measured on the median of three runs:

| metric | budget |
| --- | --- |
| Largest Contentful Paint | < 2.5 s |
| Cumulative Layout Shift | < 0.1 |
| Total Blocking Time | < 200 ms (our own scripts; AdSense is most of what is left) |
| bytes before interaction, home | ≤ ~350 KB of our own (third-party ads on top) |

What keeps it there: no render-blocking request to another origin (fonts are self-hosted, `display: swap`); only
the CSS the first screen needs is in `<head>` (the recorder's and the range picker's load at the end of the body);
scripts are `defer`; the engraver (OSMD, ~320 KB) loads when a staff is near the screen or, in `/app`, once
the app (not the sign-in screen) is open; jsPDF only on the first PDF; the piano samples only on Play; images
are AVIF/WebP at phone widths with `width`/`height` set and `loading="lazy"` below the fold.

To measure (from the repo root; Chrome from Playwright works):

```bash
CHROME_PATH=/path/to/chrome npx lighthouse@12.8.2 https://notefusion.studio/ --form-factor=mobile \
  --throttling-method=simulate --only-categories=performance --chrome-flags="--headless=new"
```

Run it for `/`, `/app`, `/hymns/amazing-grace`, `/hymns/identify` and a blog post, before and after a change
that adds weight; for a local build, serve `web-site/` with the headers in `vercel.json` and gzip/brotli.
Check layouts at 360, 390 and 414 px (and 768) for horizontal scroll, small targets and dialogs that do not fit.

## After deploying

The privacy URL has to be pasted into three places, none of which pick it up
automatically:

1. Google Cloud Console → OAuth consent screen → **Privacy policy URL**. Google
   will not verify the app without it.
2. App Store Connect → app privacy.
3. Google Play Console → Store listing.

The landing page's download buttons point at the published Google Play listing:
`https://play.google.com/store/apps/details?id=com.notefusion.com`.

## Contact addresses

The policy cites `privacy@notefusion.studio` and `security@notefusion.studio`, and the
site footer cites `hello@notefusion.studio`. All three need to exist and be
monitored before the policy goes live — GDPR gives a 30-day response window, and
pointing at a dead mailbox is worse than pointing at a personal one.
